# 10 移除模拟层并接入真实系统目录

> 用户反馈：界面里有「内置模拟手机」，手机上真实创建的截图在界面里找不到；
> 要求去掉所有模拟的东西，安卓端真实访问系统目录并申请相册/文件等权限。

## 1. 问题定位

用一次跨边界实验暴露了问题。当时界面 `/api/state` 显示：

- `CONNECT` 日志目标为 `127.0.0.1:60637` —— 那是 `Engine` 随机分配的**内置模拟手机**端口，
  不是 `adb forward` 的 10086；
- `device_name` 为「模拟手机 (Smartisan OS)」、型号「Smartisan OS Simulator」；
- 目录里出现 `自测目录`、`big.bin` 等 Python 侧自测残留；
- 设备侧用 `adb shell` 新建的文件界面看不到，界面上传的文件设备侧读不到。

结论：界面当时连的是内存模拟手机（`VirtualPhone` + `PhoneServer`），看到的全是假数据。
而安卓端即便连真机，读的也是应用专属目录下几个**播种出来的示例文件夹**
（DCIM/Camera、Pictures/Screenshots 等空壳），不是手机真实公共存储，
所以用户拍的截图 `/sdcard/Pictures/Screenshots/Screenshot_20261114-042107_Handover Demo.png`
自然找不到。

## 2. 改动内容

### Python 端（彻底移除模拟）

| 位置 | 改动 |
| --- | --- |
| `demo/mock_phone.py` | 清空为占位说明，`VirtualPhone`/`PhoneServer` 实现全部删除，无任何模块引用 |
| `demo/engine.py` | 不再创建/启动模拟手机与回环服务；`devices()` 只返回 mDNS 真实发现的设备；移除 `set_locked`/`reseed`/二维码/`phone` 状态字段 |
| `demo/discovery.py` | 移除 `lan_ip()`（二维码用）与 `register()`（注册模拟设备用），只保留真实设备浏览 |
| `demo/webui.py` | 移除「模拟手机」「连接二维码」卡片、锁屏开关、补回示例按钮；设备列表标注「只连接真实安卓设备」；手动连接框预填 `127.0.0.1:10086` |
| `run_demo.py` | 移除依赖模拟手机的 `--self-test`；启动即连真机；设置 `no_proxy` 避免本机代理拦截；`--probe` 改为对真实设备自检 |
| `requirements.txt` | 移除 `qrcode`（二维码已无意义），仅保留 `zeroconf` |
| `demo/__init__.py`、各处文案 | 「模拟手机」改为「连接真实安卓设备」 |

### 安卓端（真实系统目录 + 权限）

| 位置 | 改动 |
| --- | --- |
| `AndroidManifest.xml` | 新增 `MANAGE_EXTERNAL_STORAGE`、`READ_MEDIA_IMAGES/VIDEO/AUDIO`、`READ/WRITE_EXTERNAL_STORAGE`（旧版兼容） |
| `PhoneStorage.java` | 根目录由「应用专属 `phone/`」改为 `Environment.getExternalStorageDirectory()`（真实 `/sdcard`）；删除 `seed()` 示例目录与占位文件；回收站移到应用专属目录；`listDir` 返回 `all_files_access` 与真实 root |
| `MainActivity.java` | 运行时申请相册/媒体/通知权限；新增「授权文件访问」按钮跳转 `ACTION_MANAGE_APP_ALL_FILES_ACCESS_PERMISSION`；状态栏显示公共存储路径与授权状态 |
| `android/build.sh` | 调试 keystore 固定到 `tmp/handover-debug.keystore`，复用同一把密钥，保证覆盖安装成功 |

权限授予（测试环境）：`pm grant` 三个 READ_MEDIA_* 与 POST_NOTIFICATIONS，
`appops set com.handover.demo MANAGE_EXTERNAL_STORAGE allow`。

## 3. 验证结果

1. 覆盖安装 `Success`；`appops get` 返回 `MANAGE_EXTERNAL_STORAGE: allow`；
   媒体权限 `granted=true`。
2. `--probe 127.0.0.1:10086` 6/6 通过，`device_info.phone_model = SM-A536B`，
   `LIST_DIR /` 返回 13 项真实根目录，`all_files_access = True`，
   `root = /storage/emulated/0`。
3. 协议列出 `/Pictures/Screenshots` 得到
   `Screenshot_20261114-042107_Handover Demo.png`（84925 字节）—— 用户创建的真实截图已可见。
4. 真实文件双向验证：
   - 下载该截图到电脑，84925 字节、MD5 `b2878c2d5f3b4850`，与设备上原图字节一致；
   - 通过界面上传 `FROM_MAC_….txt` 到 `/sdcard/Pictures/Screenshots`，设备侧 `cat`
     内容与 MD5 `052d76e6f352e6e3` 双向一致。
5. 新 GUI `GET /` 返回 200；状态快照中已无 `qr`、`phone` 字段；
   `devices` 仅含 mDNS 发现的真实设备（`192.168.2.173:10086`）；
   默认连接 `127.0.0.1:10086`，`stage = paired`，当前路径 `/Pictures/Screenshots`。

## 4. 仍然真实存在的边界（非模拟、但非官方）

- 安卓端 APK 是本项目自建的 `com.handover.demo`，**不是官方 HandShaker 手机端**；
  协议是自定义 HOVR/JSON，**不是官方 SSP/Protobuf**，二者不能互通。
- 信任弹窗由桌面端发起，安卓端按选择返回 `ok/failed`，不是手机系统原生授权框。
- 剪贴板后台读取受 Android 10+ 限制，`GET_CLIPBOARD` 返回服务内缓存；
  `POST_CLIPBOARD` 会写入系统剪贴板。
- 明文 TCP，无 TLS/加密；调试密钥签名，不能分发。
- `MANAGE_EXTERNAL_STORAGE` 正式使用需在系统设置里开启；测试环境用 appops 授予。
